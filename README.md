# 책이 노래가 될 때

책에서 건진 질문을 노래와 가사 해석으로 다시 만나는 이정주의 음악 아카이브입니다.

## 제공 기능

- 번호순 노래 보관함과 검색
- MP3·MP4 파일의 **오디오 전용 재생**
- 재생 가능한 보관 음원의 무작위 순서 재생
- 선택한 노래 한 곡 무한 반복
- 필요할 때만 명시적으로 여는 MP4 영상·YouTube 영상
- 전체 가사와 가사별 의미 해석
- 곡별 공유창 또는 링크 복사와 고유 공유 미리보기
- 로그인 없이 사용하는 별도 `나의 기록` 화면
- `마음에 담은 노래`, 최근 실제 재생 6곡과 곡별 한 줄 기록
- 개인 기록을 Markdown 파일로 내보내는 기능
- 이 기기의 마음·최근·한 줄 기록을 확인 후 직접 지우는 기능
- 정밀 포인터에서만 작동하는 곡 카드 Spotlight와 흐림 없는 260ms 화면 전환
- 모바일·태블릿·데스크톱 반응형 화면
- 새 곡이 늘어나도 데이터로 누적되는 구조
- 곡별 현재 음원 업로드 날짜와 전체 방문자 누적 재생수

개인 보관함의 마음·최근 곡 번호 배열은 브라우저 `localStorage`의 `book-song:personal-library:v1`에, 곡별 한 줄은 `book-song:reflections:v1`에 따로 저장됩니다. 한 줄은 곡마다 최대 300자 1개이며 수정·삭제할 수 있습니다. 이름·이메일·기기 식별자를 요구하거나 수집하지 않고 개인 기록을 서버로 전송하지 않습니다. 브라우저나 기기가 달라지면 기록이 이어지지 않으며, 브라우저 데이터를 지우면 사라질 수 있습니다.

## 브랜드 이미지와 글꼴

- `assets/brand-main.jpg`: 사용자가 제공한 전체 로고에서 사진 메타데이터를 제거한 공개용 복사본
- `assets/brand-symbol.png`: 작은 화면용 책·음표 중심 크롭
- 헤더·첫 화면·선택 곡 표지·파비콘·앱 아이콘·공유 이미지는 위 브랜드 이미지 계열로 통일합니다.
- 한글 본문과 제목에는 가독성이 높은 `Pretendard Variable`을 로컬 파일로 사용합니다.
- `Pretendard`의 라이선스는 `fonts/LICENSE.txt`에서 확인할 수 있습니다.

## 상호작용 효과와 움직임 설정

곡 카드의 Spotlight와 화면 전환 Fade는 React Bits의 시각 원리를 참고해 React·GSAP 없이 CSS와 바닐라 JavaScript로 구현했습니다. Spotlight 장식은 카드의 버튼 이벤트를 가로채지 않으며 마우스·트랙패드처럼 정밀 포인터가 있는 환경에서만 위치를 추적합니다. 터치 환경에서는 포인터 추적을 연결하지 않고, `prefers-reduced-motion: reduce`에서는 화면 전환 애니메이션과 Spotlight 이동을 제거합니다. 관련 고지는 [`THIRD_PARTY_NOTICES.md`](./THIRD_PARTY_NOTICES.md)에 있습니다.

`랜덤 노래 재생`은 사이트 최상단의 고정 메뉴에 있어 스크롤 위치와 관계없이 사용할 수 있습니다. 바로 옆의 `한 곡 반복` 버튼을 켜면 현재 선택한 노래가 끝난 뒤 같은 곡을 계속 재생합니다. 한 곡 반복과 랜덤 재생은 동시에 실행되지 않으며, 랜덤 재생을 시작하면 한 곡 반복이 자동으로 꺼집니다. 상태 표시에는 `재생 중 · 〈노래 제목〉`이 나타나며, 그 옆의 재생 제어 버튼으로 현재 곡을 일시정지하고 이어서 재생할 수 있습니다. 재생 대기·일시정지·재생 완료 상태도 구분됩니다. 랜덤 재생은 현재 `media/NN.mp3` 또는 `media/NN.mp4`가 연결된 곡을 중복 없이 한 번 섞어 이어서 재생합니다.

`음악 보관함`, `나의 기록`, `가사와 의미`, `프로젝트 소개`는 긴 한 페이지의 위치로 스크롤하는 링크가 아니라 각각의 독립 화면으로 전환됩니다. 화면 전환은 페이지를 새로 불러오지 않는 방식이라 재생 중인 음악과 랜덤 재생 상태가 그대로 유지됩니다. 주소의 `view` 값으로 각 화면을 직접 열 수 있고 브라우저 뒤로가기·앞으로가기도 지원합니다. `나의 기록`은 `?view=journal`로 직접 열 수 있습니다.

선택한 노래와 `가사와 의미` 화면의 `이 노래 공유하기` 버튼은 모바일에서 운영체제 공유창을 사용하고, 지원되지 않는 환경에서는 곡별 주소를 복사합니다. 공유 주소는 `/share/NN/` 형식이며 곡 제목과 질문을 미리보기 정보로 제공한 뒤 해당 곡의 `가사와 의미` 화면을 엽니다. 공유 동작은 재생을 시작하거나 랜덤·반복 상태를 바꾸지 않으며, 이름·연락처·공유 대상 정보를 사이트로 전송하거나 저장하지 않습니다.

모바일에서 본문을 아래로 읽기 시작하면 고정 헤더는 브랜드 제목 행만 접고, 홈 아이콘·랜덤 재생·현재 상태·재생 제어·주요 메뉴는 그대로 유지합니다. 선택한 노래 화면에는 `곡 목록 바로가기`와 `가사와 의미 살펴보기`를 두어 긴 카드와 곡 목록 사이를 빠르게 이동할 수 있습니다. 검색 안내 문구와 활성 탭은 일반 텍스트 대비와 키보드 초점 상태가 분명하도록 설계합니다.

## 업로드 날짜와 누적 재생수

- `data/tracks.json`의 `uploadedAt`은 현재 공개 중인 음원 파일이 Git 저장소에서 마지막으로 추가·교체된 실제 날짜입니다. 제작일이나 외부 플랫폼 최초 공개일을 추정하지 않습니다.
- 누적 재생수는 GitHub Pages가 `https://book-song-plays-api.vercel.app/api/plays`를 호출하고, Vercel API가 Supabase의 원자적 증가 함수에 기록합니다.
- 한 곡의 실제 미디어 진행 시간이 누적 **30초**에 도달하면 1회로 기록합니다.
- 일시정지·이어 듣기·사이트 화면 전환은 같은 재생으로 이어집니다. 탐색바로 건너뛴 시간은 포함하지 않습니다.
- 랜덤 재생과 자동 다음 곡도 각 곡을 실제 30초 들으면 같은 기준으로 집계합니다.
- 한 곡 반복 모드에서는 반복 경계마다 새 감상 회차를 시작합니다. 각 회차에서 실제 진행 시간 30초를 들었을 때 회차당 한 번만 집계합니다.
- 한 번 자격을 얻은 재생의 네트워크 재시도에는 같은 임의 UUID를 사용하므로 중복 증가하지 않습니다.
- 집계 API가 실패해도 음원 재생, 선곡, 랜덤 큐와 화면 전환은 계속 동작합니다.

### 개인정보 범위

애플리케이션은 재생수 집계를 위해 쿠키나 `localStorage` 식별자를 만들지 않습니다. Supabase 테이블에는 곡 번호, 전체 누적값, 중복 방지용 임의 UUID와 집계 시각만 저장하며 이름·이메일·원본 IP·기기 정보는 저장하지 않습니다. Vercel과 Supabase의 보안·운영 로그에는 각 서비스의 자체 정책이 적용됩니다.

### 백엔드 구성

- Vercel 프로젝트: `book-song-plays-api`
- Supabase 프로젝트: `book-song-plays` (`Northeast Asia (Seoul)`)
- SQL 마이그레이션: 초기 `20260811_create_play_counter.sql`, 10번 확장 `20260811120000_add_track_10_play_counter.sql`, 11번 확장 `20260811144000_add_track_11_play_counter.sql`, 12번 확장 `20260812002000_add_track_12_play_counter.sql`, 13번 확장 `20260812023600_add_track_13_play_counter.sql`, 14번 확장 `20260816193700_add_track_14_play_counter.sql`
- Vercel 함수: `services/play-counter-api/api/plays.js`
- 필요한 Vercel 환경변수: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`
- 서비스 역할 키는 Vercel의 Sensitive 환경변수에만 보관하며 브라우저에는 어떤 Supabase 키도 넣지 않습니다. 테이블과 RPC 함수는 익명·인증 사용자에게 공개하지 않습니다.

## MP3 또는 MP4를 올리는 가장 쉬운 방법

1. GitHub 저장소의 `media` 폴더를 엽니다.
2. **Add file → Upload files**를 누릅니다.
3. 곡 번호와 같은 이름으로 파일을 올립니다.
   - 첫 번째 곡 MP3: `01.mp3`
   - 첫 번째 곡 MP4: `01.mp4`
4. 변경 사항을 저장하면 배포 작업이 자동으로 시작됩니다.
5. 배포가 끝나면 웹사이트에서 해당 곡의 **보관 음원**이 나타납니다.

기본 규칙은 다음과 같습니다.

- MP3와 MP4 모두 `<audio>` 플레이어에서 **영상 없이 음악만** 재생합니다.
- 같은 번호의 MP3와 MP4가 모두 있으면 MP3를 우선합니다.
- 파일은 95MB보다 작게 준비하는 것을 권장합니다.
- MP4의 화면은 자동으로 공개되지 않습니다.

## 나중에 영상을 공개하는 방법

영상은 사용자가 원하는 시점에만 명시적으로 연결합니다. `data/media.json`은 다음처럼 오디오·영상·YouTube를 서로 분리합니다.

```json
"05": {
  "audio": "",
  "video": "media/05.mp4",
  "youtube": ""
}
```

- `audio`: 음악만 재생할 MP3 또는 MP4. 번호 파일은 빌드가 자동으로 찾으므로 보통 비워 둡니다.
- `video`: 화면에 표시할 로컬 MP4. 이 값을 명시해야만 `영상 보기` 선택지가 생깁니다.
- `youtube`: 화면에 표시할 YouTube 주소. 이 값을 명시해야만 `YouTube` 선택지가 생깁니다.

같은 MP4를 음악과 영상 양쪽에 사용하고 싶다면 파일은 `media/05.mp4`로 두고 `video`만 같은 경로로 설정하면 됩니다. 기본 선택은 계속 `음악만 듣기`입니다.

YouTube 예시:

```json
"05": {
  "audio": "",
  "video": "",
  "youtube": "https://www.youtube.com/watch?v=영상ID"
}
```

## 새 노래 추가

번호가 붙은 공개 곡 노트를 준비한 뒤 다음 명령으로 노래 데이터를 갱신합니다.

```bash
python3 scripts/sync_from_obsidian.py --source-dir "곡 노트 폴더" --uploaded-at 14=2026-08-16
python3 scripts/build.py
python3 scripts/verify.py
```

기존 곡의 `uploadedAt`은 동기화할 때 자동으로 보존됩니다. 새 곡이나 교체한 음원은 Git 이력에서 확인한 날짜를 `--uploaded-at NN=YYYY-MM-DD`로 명시합니다.

웹사이트 공개 화면에는 제목, 참고 도서, 중심 질문, 가사, 의미 해석, 내레이션과 마지막 질문만 담깁니다.

## 로컬 미리보기

```bash
python3 scripts/build.py
python3 -m http.server 4173 --directory dist
```

브라우저에서 `http://127.0.0.1:4173/`을 엽니다.
